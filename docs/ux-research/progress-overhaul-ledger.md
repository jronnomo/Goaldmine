**Feature:** Rebuild `/progress` around four pillars — baseline improvements, Program progress, gamification, PR highlights.
**Issue:** none (research-first; owner request 2026-08-10).
**Report:** [`progress-overhaul.md`](./progress-overhaul.md) · **Mockup:** [`progress-overhaul.html`](./progress-overhaul.html)

Stable IDs `UXR-PROG-NN` — assigned once, **never renumbered**. Status starts `proposed`. The **implementing PR ticks each row** to `shipped` / `reworked` / `dropped` with a SHA, a `file:line`, or a one-line reason in Evidence.

Rows tagged `tuning⚠` / `decoration⚠` / `a11y` are the ones a future audit cares about most — **confirm them on a real 390px device in both themes.** Because the palette is iso-luminant (`--target`↔`--accent` is 1.16:1 in light, `--success`↔`--muted` is 1.00:1), the acceptance test for every identity row is: **a grayscale screenshot must lose nothing.** The pixel mockup ships a grayscale toggle for exactly this.

Rows prefixed **⚑ SIGN-OFF** need an owner decision before implementation. Rows prefixed **Pre-existing bug/gap/hazard** are not part of this feature and should be filed independently.
