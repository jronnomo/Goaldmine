# Recommendation Ledger — `/trends` Trends Dashboard

**Feature:** Weight, calories and macros on one shared time axis, with a drag-selected sub-window and a window aggregate that states its own coverage.
**Issue:** none (solo flow; PRDs `PRD-g1-trends-dashboard.md` + `PRD-g2-apple-health-import.md`).
**Report:** [`trends-dashboard.md`](./trends-dashboard.md)

Stable IDs `UXR-TRENDS-NN` — assigned once, **never renumbered**. Status starts `proposed`. The **implementing PR ticks each row** to `shipped` / `reworked` / `dropped` with a SHA, a `file:line`, or a one-line reason in Evidence.

Rows tagged `tuning⚠` / `decoration⚠` / `a11y` are the ones a future audit cares about most — **confirm them on a real 390px device, in both themes, and against a grayscale screenshot.** Because the palette is iso-luminant (`--accent`↔`--target` 1.16:1, `--accent`↔`--warning` 1.01:1, `--muted`↔`--success` 1.00:1), the acceptance test for every identity row is: **a grayscale screenshot must lose nothing.**

Rows prefixed **⚑ SIGN-OFF** need a founder decision before implementation. Rows prefixed **🔴** are pre-existing defects or hazards surfaced by this research; they are not part of the feature and should be filed independently unless noted.

**Authority note:** where this ledger and `.feature-dev/2026-09-02-trends-dashboard/agents/architecture-blueprint-v2.md` differ, research wins on presentation and the blueprint wins on mechanism. Rows that ask the blueprint to move are marked ⚑.
